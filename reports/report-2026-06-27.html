🟠 pnpm: 提升安装时锁文件别名路径遍历漏洞
GHSA-fr4h-3cph-29xv | CVE: 待分配
优先级: 高
High (CVSS 7.1) ⭐ 35,627 🔴 PoC Available 📖 详细分析

漏洞描述：pnpm 包管理器在处理提升模式（hoisted install）时存在路径遍历漏洞。恶意构造的锁文件别名可以绕过 node_modules 目录限制，通过路径遍历将包文件写入到安装根目录之外的位置。攻击者可以利用保留别名（如 .bin 或 .pnpm）覆盖 pnpm 管理的目录布局。

影响产品：pnpm ⭐35,627

影响版本：

  • pnpm < 10.34.4
  • pnpm >= 11.0.0, < 11.7.0

攻击面：供应链攻击 - 攻击者可以通过构造恶意的锁文件（pnpm-lock.yaml）来利用此漏洞。当用户或CI/CD系统执行 pnpm install 时，恶意别名会被解析并创建超出预期目录的文件。

触发条件：

  • 使用提升模式安装依赖（hoisted install）
  • 存在恶意构造的锁文件，包含路径遍历别名
  • 用户执行 pnpm install 命令

潜在危害：

  • 文件系统写入越界：可将文件写入项目目录之外的位置
  • 目录覆盖：可能覆盖 .bin、.pnpm 等关键目录
  • 代码注入：通过写入恶意脚本到 .bin 目录实现代码执行
  • 供应链投毒：可在依赖安装过程中植入后门

可利用性：高 - 公告包含详细的漏洞原理分析，明确指出：

  • 遍历别名可逃逸 node_modules 目录
  • 保留别名可覆盖 pnpm 布局
  • 提供具体的文件路径（safeJoinModulesDir.ts）
  • 包含利用回归测试用例
  • 有私有PR仓库展示修复方案

修复建议：

  • 立即升级 pnpm 到 10.34.4 或 11.7.0 及以上版本
  • 审查项目中的 pnpm-lock.yaml 文件，检查是否存在可疑的路径遍历别名
  • 在CI/CD环境中固定 pnpm 版本，避免自动升级引入风险
  • 使用 pnpm audit 命令检查依赖安全性
