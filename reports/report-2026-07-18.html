🔴 vLLM: Remote Code Execution in Video Processing
GHSA-4r2x-xpjr-7cvv | CVE: CVE-2026-22778
优先级: 🔴 紧急
Critical ⭐ 86,527 🔴 完整PoC利用链 📖 详细分析

漏洞描述：vLLM存在一条完整的远程代码执行(RCE)利用链。攻击者通过向vLLM的视频模型API端点发送恶意视频URL，可实现任意命令执行。利用链包含两个阶段：(1) PIL错误消息泄露内存地址，绕过ASLR保护；(2) OpenCV/FFmpeg的JPEG2000解码器存在堆溢出，劫持代码执行流。

影响产品：vllm ⭐86,527

影响版本：≥ 0.8.3, < 0.14.1

攻击面：HTTP API端点（Completions/Invocations），面向视频模型。默认安装的vLLM（pip/docker）无认证机制。

触发条件：向vLLM发送包含恶意视频URL的请求即可触发，无需认证。

潜在危害：完全控制服务器，执行任意系统命令。在容器化环境（如llm-d）中可能横向移动。

可利用性：有完整PoC利用链，包含ASLR绕过+堆溢出两阶段攻击。利用门槛低，仅需HTTP请求。

修复建议：立即升级至 vllm ≥ 0.14.1。确保vLLM实例部署在网络隔离环境中，启用API认证。

🔴 golang.org/x/crypto: SSH 多个严重安全漏洞
GHSA-x527-x647-q7gg / GHSA-5cgq-3rg8-m6cv / GHSA-vgwf-h737-ff37 / GHSA-f5wc-c3c7-36mc | CVE: CVE-2026-46595, CVE-2026-42508, CVE-2026-39830, CVE-2026-39832
优先级: 🔴 紧急
Critical ×4 ⭐ 135,284 📖 详细分析

漏洞描述：golang.org/x/crypto 包在 0.52.0 版本之前存在4个严重SSH安全漏洞：

  • CVE-2026-46595：SSH服务器使用VerifiedPublicKeyCallback时，源地址验证被跳过，导致授权绕过。
  • CVE-2026-42508：CA的SignatureKey未正确检查@revoked状态，被吊销的证书仍可通过验证。
  • CVE-2026-39830：恶意SSH对端可发送未预期的全局请求响应填满内部缓冲区，阻塞连接读循环，造成资源泄露（DoS）。
  • CVE-2026-39832：转发SSH密钥时，约束扩展（如restrict-destination）未被序列化，目标限制被静默移除。

影响产品：golang.org/x/crypto ⭐135,284 (Go语言标准扩展库)

影响版本：< 0.52.0

攻击面：所有使用golang.org/x/crypto/ssh包的Go应用程序，包括SSH服务器、SSH代理、密钥转发场景。

触发条件：因漏洞而异——认证配置不当、吊销证书验证缺失、恶意SSH协议行为等。

潜在危害：认证绕过、权限提升、拒绝服务、密钥约束失效导致横向移动。

可利用性：有详细技术描述和修复代码参考，RedHat已发布多个安全通告。

修复建议：立即升级 golang.org/x/crypto 至 ≥ 0.52.0。检查所有使用SSH功能的Go项目。
