🔴 Docker: Race condition in docker cp allows bind mount redirection to host path
GHSA-rg2x-37c3-w2rh | CVE: CVE-2026-42306
优先级: 极高
High ⭐ 71,681 📖 详细原理

漏洞描述：docker cp 在挂载设置期间存在竞争条件。守护进程在创建挂载目标后、执行 mount() 系统调用前，容器内进程可将目标路径替换为指向宿主机任意路径的符号链接，导致 bind mount 被重定向到宿主机任意位置。

影响产品：moby/moby (Docker Engine) ⭐71,681

影响版本：<= 28.5.2（暂无补丁）

攻击面：需要容器内有进程执行能力。攻击者需在容器内运行恶意进程，在 docker cp 操作的极短窗口内替换挂载点为符号链接。

触发条件：1) 攻击者拥有容器内进程执行权限；2) 在 docker cp 挂载点创建与 mount() 调用之间替换路径为符号链接；3) 需要精确的时序竞争。

潜在危害：若卷可写，可覆写宿主机任意文件；若卷只读，可遮蔽宿主机路径造成DoS。挂载虽是临时的（docker cp完成后拆除），但写入效果持久化。

可利用性：有详细原理分析，包含漏洞代码路径说明。竞争窗口较窄，需要精确时序，实际利用有难度但原理清晰。

修复建议：目前暂无官方补丁（patched: null）。建议限制非信任容器的 docker cp 操作，监控异常的符号链接行为。可升级到 moby v2 的 2.0.0-beta.14+ 版本。

🔴 esbuild: Missing binary integrity verification in Deno module enables RCE via NPM_CONFIG_REGISTRY
GHSA-gv7w-rqvm-qjhr | CVE: 待分配
优先级: 极高
High ⭐ 39,926 🔴 PoC Available 📖 详细分析

漏洞描述：esbuild 的 Deno 模块（lib/deno/mod.ts）从 npm 注册表下载原生二进制文件并以可执行权限（0o755）写入磁盘，但未执行任何完整性校验（如 SHA-256 哈希检查）。Node.js 版本包含 binaryIntegrityCheck() 函数，但 Deno 版本遗漏了此保护。

影响产品：evanw/esbuild ⭐39,926

影响版本：>= 0.17.0, < 0.28.1

攻击面：NPM_CONFIG_REGISTRY 环境变量。当该变量被设置时，Deno 模块会使用该值构造下载URL。攻击者若能控制此环境变量（CI/CD管道、共享开发环境、企业内网自定义npm镜像），即可注入恶意二进制文件。

触发条件：1) 使用 Deno 运行 esbuild；2) NPM_CONFIG_REGISTRY 环境变量被设置为攻击者控制的 registry；3) 恶意 registry 返回恶意二进制文件代替正常 esbuild 二进制。

潜在危害：完全远程代码执行。恶意二进制以 Deno 进程权限运行，可完全控制开发/CI环境。

可利用性：有完整漏洞原理和代码路径分析。利用场景明确：在CI/CD环境中设置 NPM_CONFIG_REGISTRY 为恶意registry即可触发RCE。

修复建议：升级到 esbuild 0.28.1+。检查 CI/CD 环境中的 NPM_CONFIG_REGISTRY 设置，确保不被篡改。

🔴 File Browser: Command Execution Allowlist Bypass via Shell Metacharacter Injection
GHSA-8c9q-7855-wfxq | CVE: CVE-2026-54090
优先级: 极高
High ⭐ 35,092 🔴 PoC Available 📖 详细分析

漏洞描述：File Browser 的命令白名单仅校验用户输入的第一个token（通过 SplitCommandAndArgs），但将整个原始字符串传递给 shell 执行。攻击者可通过分号、管道、反引号、$() 等 shell 元字符在白名单命令后链式执行任意命令。

影响产品：filebrowser/filebrowser ⭐35,092

影响版本：< 2.33.8

攻击面：需要 File Browser 实例开启了命令执行功能（默认从 v2.33.8 起已禁用）。需要认证用户权限。

触发条件：1) 管理员开启了命令执行功能（shell interpreter配置如 /bin/sh -c）；2) 认证用户在命令输入中注入 shell 元字符，如：allowed_cmd; malicious_cmd

潜在危害：以 File Browser 进程权限执行任意系统命令，可能导致服务器完全控制。

可利用性：有完整原理和代码级分析。漏洞位于 runner/parser.go 的 ParseCommand 函数（第10-25行）和 http/commands.go 的 commandsHandler（第72-86行）。利用简单，只需在允许的命令后附加 shell 元字符。

修复建议：升级到 v2.33.8+（该版本默认禁用命令执行功能）。如必须使用命令执行，确保升级到修复版本并理解相关风险。

可利用性：有完整 PoC 脚本，包括生成超大密码文件的命令和 Docker 部署测试步骤。利用零门槛，无需认证。

修复建议：升级到 v2.63.6+。在反向代理层限制请求体大小。

🟠 Parse Server: Pre-authentication denial of service via client version header regex backtracking
GHSA-38m6-82c8-4xfm | CVE: CVE-2026-47138
优先级: 高
High ⭐ 21,400 📖 详细分析

漏洞描述：Parse Server 的客户端 SDK 版本解析器存在 ReDoS 漏洞。攻击者可通过 X-Parse-Client-Version 请求头或 _ClientVersion JSON 字段注入对抗性输入，触发多项式回溯，在认证和限流之前消耗数秒到数分钟的同步 CPU 时间。

影响产品：parse-community/parse-server ⭐21,400

影响版本：>= 9.0.0, < 9.9.1-alpha.1；< 8.6.77

攻击面：所有 /parse/* 请求的 X-Parse-Client-Version 头和 _ClientVersion 字段。解析在会话认证和限流之前执行。

触发条件：1) 攻击者知道 Parse Application ID（通常公开可知）；2) 发送包含对抗性输入的单个 HTTP 请求；3) 少量并发请求即可饱和 worker。单个大请求可 pin 住 worker 数分钟。

潜在危害：生产环境完全拒绝服务。Node.js worker 被同步阻塞，无法处理其他请求。

可利用性：有详细原理分析，包含漏洞代码路径和修复方案说明。预认证、无速率限制、利用简单。

修复建议：升级到 9.9.1-alpha.1+ 或 8.6.77+。部署反向代理/WAF 限制 X-Parse-Client-Version 头和 _ClientVersion 字段的大小。

🟠 PyO3: Out-of-bounds Read in nth/nth_back for PyList and PyTuple iterators
GHSA-36hh-v3qg-5jq4 | CVE: 待分配
优先级: 高
High ⭐ 15,787 📖 详细分析

漏洞描述：PyO3 0.24.0 为 BoundListIterator 和 BoundTupleIterator 添加了优化的 nth/nth_back 实现。这些实现使用未检查的 usize 加法（index + n）计算目标索引，在足够大的 n 值下可导致溢出/下溢，通过 get_item_unchecked 读取列表/元组存储之外的任意内存。

影响产品：PyO3/pyo3 ⭐15,787

影响版本：< 0.29.0

攻击面：使用 PyO3 进行 Python-Rust 互操作的 Rust 应用程序。攻击者需能影响迭代器的 nth 参数值。

触发条件：1) 使用 PyO3 0.24.0+ 版本；2) 代码中对 PyList/PyTuple 迭代器调用 nth 或 nth_back 方法；3) n 值与内部索引的组合导致 usize 溢出。

潜在危害：nth_back 可读取 list/tuple 存储之后的任意内存，可能导致信息泄露或崩溃。nth 可读取已迭代过的前方元素。

可利用性：有详细原理分析，包含溢出机制说明。Rust 内存安全问题，利用难度较高但影响面广。

修复建议：升级到 PyO3 0.29.0+。检查代码中是否使用了 PyList/PyTuple 迭代器的 nth/nth_back 方法。
