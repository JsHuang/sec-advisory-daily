🔴 MCP Ruby SDK: SSE Session Poisoning（会话劫持）
GHSA-5p9g-j988-pcwv | CVE: CVE-2026-67431
优先级: 🔴 紧急
High ⭐ 871 (modelcontextprotocol) 🔴 完整PoC 📖 详细分析

漏洞描述：MCP Ruby SDK 的 StreamableHTTP 和 SSE HTTP 传输实现中缺少 Session 所有权验证。任何攻击者只要获取到受害者的 Session ID，就可以通过向 /messages/{session_id} 发送请求来劫持受害者的会话，执行工具调用并注入响应。这是一种静默攻击——受害者难以察觉会话已被劫持。

影响产品：MCP Ruby SDK (rubygems/mcp) ⭐ 871

影响版本：<= 0.22.0

攻击面：网络可达的 MCP Server（HTTP/SSE 传输层）

触发条件：攻击者获取到目标 Session ID（通过网络嗅探、日志泄露等途径），然后向 /messages/{session_id} 发送恶意 tool call 请求

潜在危害：会话劫持，攻击者可以：(1) 在受害者会话中执行任意工具调用；(2) 注入恶意响应到受害者的 SSE 流；(3) 操纵受害者会话状态。完整性影响高，可用性影响低。

可利用性：有完整PoC — 公告提供了 attacker_client.py 和 legitimate_client.py 两个完整的演示脚本，包含运行步骤和预期结果

漏洞原理：服务端在处理 POST /messages/{session_id} 请求时，仅验证 session_id 是否存在于活跃会话表中，但不验证请求者是否为该 session 的合法所有者。与其他 SDK 实现（C#、Go）不同，Ruby SDK 缺少 user binding 机制。

修复建议：升级至 MCP Ruby SDK >= 0.23.0。该版本增加了 session ownership 验证，将 session ID 绑定到特定用户/连接。

🔴 MCP Ruby SDK: 无界JSON-RPC请求体导致内存耗尽DoS
GHSA-h669-8m4g-r2hc | CVE: CVE-2026-67432
优先级: 🔴 紧急
High ⭐ 871 (modelcontextprotocol) 🔴 完整PoC 📖 详细分析

漏洞描述：MCP Ruby SDK 的 StreamableHTTPTransport 在处理 POST 请求时，会将整个 HTTP body 读入内存并使用 JSON.parse(body, symbolize_names: true) 解析，没有任何大小限制、Content-Length 预检查或流式解析器。未认证的远程攻击者可以通过发送单个超大 JSON-RPC POST 请求，强制服务端分配数GB内存，导致 DoS。

影响产品：MCP Ruby SDK (rubygems/mcp) ⭐ 871

影响版本：<= 0.22.0

攻击面：任何使用 StreamableHTTPTransport 的 MCP Server，包括 stateless: true 模式

触发条件：攻击者向 MCP Server 发送一个超大 HTTP POST 请求体（如 512MB+ 的 JSON 字符串），无需认证或 Session ID

潜在危害：服务端 worker 进程内存耗尽，导致 DoS。由于 symbolize_names: true，每个 JSON key 还会分配 Ruby symbol（不可GC），进一步加剧内存压力。漏洞路径在 session 验证之前执行，攻击门槛极低。

可利用性：有完整PoC — 公告提供了 oom_poc_server.rb 和 oom_poc_client.py 两个自包含脚本，可直接运行演示

漏洞原理： 1. handle_post 方法第341行：body_string = request.body.read 无上限读取
2. 第531-535行：JSON.parse(body_string, symbolize_names: true) 完全物化解析对象
3. 同样的问题存在于 stdio_transport.rb:23（$stdin.gets 无 limit: 参数）

修复建议：升级至 MCP Ruby SDK >= 0.23.0。该版本增加了请求体大小限制和流式解析。

🟠 Quarkus: 路径规范化绕过认证/授权策略
