🟠 [高危] Dex Token Exchange 端点缺失 AllowedConnectors 访问控制
GHSA-7qjx-gp9h-65qj | CVE: 暂无
优先级: 高
High ⭐ 10,872 🔴 PoC Available 📖 详细分析

漏洞描述：Dex（OIDC Identity Provider）的 token exchange 端点 handleTokenExchange（server/handlers.go:1804-1893）在签发 token 前未调用 isConnectorAllowed(client.AllowedConnectors, connID) 进行连接器 ACL 校验。而同文件中的其他 handler（如 handleConnectorLogin、parseAuthorizationRequest）均正确执行了该检查。这导致已授权客户端可通过 token exchange 端点绕过连接器白名单限制，使用被禁止的身份连接器签发 token。

影响产品：dexidp/dex ⭐10,872

影响版本：< 0.0.0-20260303131938-204dbb2e3ff7（尚无正式修复版本）

攻击面：网络远程攻击。攻击者需要获取已泄露的客户端密钥（client_secret），并持有被禁止连接器的合法 subject_token。典型场景：CI/CD 泄露、环境变量泄露、服务账号密钥泄露。

触发条件：

  • 目标 Dex 实例启用了 token exchange grant type
  • 客户端配置了 allowedConnectors 白名单限制
  • 攻击者获取了该客户端的 client_secret
  • 攻击者持有被禁止连接器的合法身份 token

潜在危害：攻击者可绕过管理员设置的连接器访问控制策略，使用被禁止的高权限连接器（如企业 Okta）签发 token。下游服务信任 Dex 签发的 token，会将攻击者识别为高权限连接器用户，实现权限提升。CVSS 3.1 评分：8.7 HIGH（AV:N/AC:L/PR:H/UI:N/S:C/C:H/I:H/A:N）。

可利用性：公告包含完整的攻击请求示例（HTTP POST 请求），详细说明了漏洞代码路径和缺失的校验逻辑，提供了具体攻击场景分析。

修复建议：

  • 在 handleTokenExchange 中 token 签发前添加 isConnectorAllowed(client.AllowedConnectors, connID) 调用
  • 参考同文件 handleConnectorLogin:377 的实现方式
  • 如暂时无法升级，可通过反向代理限制 token exchange 端点的访问
  • 审查所有使用 allowedConnectors 的客户端配置，确认无泄露风险

🟠 [高危] PhoenixStorybook LiveView 事件参数无限制 Atom 创建导致 DoS
GHSA-833p-95jq-929q | CVE: CVE-2026-8469
优先级: 中
High ⭐ 862 🔴 PoC Available

漏洞描述：PhoenixStorybook 的 LiveView 事件处理函数（handle_set_variation_assign/3、handle_toggle_variation_assign/3、to_variation_id/2、to_value/4）对用户提供的参数直接调用 String.to_atom/1 转换为 Atom，未检查 atom 是否已存在。BEAM VM 的 atom 不会被垃圾回收，攻击者可通过发送大量包含唯一键的事件参数，永久耗尽 atom 表（上限约 1,048,576），导致整个 Erlang/Elixir 节点崩溃。

影响产品：phenixdigital/phoenix_storybook ⭐862

影响版本：>= 0.2.0, < 1.1.0

攻击面：网络远程攻击，无需认证。攻击者只需能访问 Storybook 路由即可发送恶意 LiveView 事件。

触发条件：

  • 目标应用挂载了 Phoenix Storybook 且可被外部访问
  • 攻击者可向 playground 发送 psb-assign、psb-toggle 等 LiveView 事件
  • 每次请求携带大量唯一键名即可触发 atom 泄漏

潜在危害：BEAM 节点完全崩溃，所有运行在该节点上的应用不可用。Atom 表一旦耗尽不可恢复，必须重启 VM。属于永久性 DoS 攻击。

可利用性：公告包含完整 PoC 脚本，直接调用 handle_set_variation_assign/3 演示 atom 泄漏过程，每次请求注入 5,000 个唯一键。

修复建议：

  • 升级至 PhoenixStorybook >= 1.1.0
  • 如无法升级，将所有 String.to_atom/1 替换为 String.to_existing_atom/1
  • 限制 Storybook 路由的访问，仅允许内网/认证用户访问
  • 监控 BEAM atom 表使用量，设置告警阈值
