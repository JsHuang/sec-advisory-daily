🔴 Fission Kubernetes 容器逃逸系列漏洞（4个关联公告）

优先级: 极高
Critical (CVSS 9.9) ⭐ 8,869 📖 详细原理

漏洞描述：Fission（Kubernetes Serverless框架）存在一系列严重的容器逃逸漏洞，涉及 Environment CRD 和 Function PodSpec 的多个攻击面。攻击者可通过构造恶意的 PodSpec 注入 hostPID/hostNetwork/privileged 等危险字段，绕过准入验证直接创建特权 Pod，最终实现从租户命名空间逃逸至宿主机节点甚至接管整个集群。

影响产品：fission/fission ⭐8,869（Fast and Simple Serverless Functions for Kubernetes）

影响版本：<= 1.23.0

攻击面：

  • GHSA-wmgg-3p4h-48x7（CVSS 9.9）：Environment CRD 的 spec.runtime.podSpec 和 spec.builder.podSpec 缺乏安全验证，且 Webhook 仅注册了 create verb，通过 kubectl patch 可绕过准入控制
  • GHSA-gx55-f84r-v3r7（CVSS 9.9）：Environment CRD podspec 直通合并，hostPID/hostNetwork/privileged 字段无过滤直接传播到生成的 Pod
  • GHSA-v455-mv2v-5g92（CVSS 9.9）：Container Executor 的 Function.spec.podspec 注入，MergePodSpec 无条件转发危险字段到 Deployment spec
  • GHSA-m63v-2g9w-2w6v（CVSS 9.9）：Environment CRD 的 Runtime.Container.SecurityContext 和 Builder.Container.SecurityContext 绕过 PodSpec 验证层，允许创建特权容器

触发条件：攻击者需要 Fission 命名空间的 create/update 权限（如 environments.fission.io 或 functions.fission.io），无需集群管理员权限

潜在危害：容器逃逸 → 宿主机访问 → 集群完全接管。攻击者可读取所有 Secret、创建后门 Pod、横向移动到其他命名空间

可利用性：有详细源码级漏洞原理分析，明确指出 ValidatePodSpecSafety() 函数不检查独立 Container 的 SecurityContext，MergePodSpec 无条件传播危险字段。攻击路径清晰

修复建议：升级至 Fission > 1.23.0。临时缓解：为 fission-function 和 fission-builder 命名空间添加 Pod Security Admission 标签（pod-security.kubernetes.io/enforce: restricted），限制 RBAC 对 Environment/Function CRD 的写入权限

优先级: 极高
Critical (CVSS 9.9) ⭐ 6,929 📖 详细原理

漏洞描述：KubeVirt 的 virt-handler 组件存在符号链接跟踪漏洞。具有命名空间 edit 权限的攻击者可通过将虚拟机控制台 socket 替换为指向宿主机 CRI-O socket 的符号链接，劫持 virt-handler 的特权连接，进而访问宿主机上任意 Unix socket。

🔴 golang.org/x/crypto/ssh 系列漏洞（权限绕过 + DoS）

漏洞描述：Go 语言官方 SSH 库 golang.org/x/crypto/ssh 发布 5 个安全公告，涵盖认证绕过、权限跳过、Agent 约束丢失、死锁和 DoS 等多种漏洞类型。这是 Go 生态中最核心的 SSH 实现，影响面极广。

影响产品：golang.org/x/crypto/ssh（Go 标准加密扩展库，被大量 Go 项目依赖）

影响版本：< 0.52.0

各漏洞详情：

  • CVE-2026-46595（CVSS 10.0）：VerifiedPublicKeyCallback 权限跳过 — 使用非 PublicKey 类型的回调时，源地址验证会被跳过（CVE-2024-45337 的绕过变体），可绕过访问控制
  • CVE-2026-42508（CVSS 9.1）：knownhosts 未强制检查 @revoked 状态 — CA 的 SignatureKey 被吊销后未被正确检查，可使用已吊销密钥通过认证
  • CVE-2026-39830：客户端可触发服务端死锁 — 发送异常响应导致服务端阻塞
  • CVE-2026-39832：SSH Agent 转发密钥时未丢弃调用者约束 — 密钥约束在转发过程中丢失，可能被滥用
  • CVE-2026-39829：病态 RSA/DSA 参数导致 DoS — 服务端处理畸形密钥参数时资源耗尽

攻击面：所有使用 golang.org/x/crypto/ssh 的 Go SSH 服务端和客户端，包括 SSH 代理转发、knownhosts 验证等场景

触发条件：针对 CVE-2026-46595：服务端使用了非标准 PublicKey 回调类型；针对 CVE-2026-42508：known_hosts 文件中存在 @revoked 标记的 CA 密钥

潜在危害：认证绕过可让未授权用户访问 SSH 服务；已知密钥吊销失效使被盗密钥仍可被使用；DoS 可使 SSH 服务不可用

可利用性：有详细的漏洞成因分析，CVE-2026-46595 明确描述了回调类型判断逻辑缺陷，CVE-2026-42508 指出 key.SignatureKey 的 @revoked 检查遗漏

修复建议：立即升级至 golang.org/x/crypto v0.52.0 或更高版本。这是 Go 官方库，升级风险低
