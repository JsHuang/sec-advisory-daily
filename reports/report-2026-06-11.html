🔴 FrankenPHP: Unsafe Unicode Handling in CGI Path Splitting Allows Execution of Non-PHP Files
GHSA-3g8v-8r37-cgjm | CVE: CVE-2026-45062
优先级: 9.5/10
High ⭐ 11,141 🔴 完整PoC + 源码分析 📖 详细分析

漏洞描述：FrankenPHP 的 cgi.go 中 splitPos() 函数在处理包含非 ASCII 字节的请求路径时，错误使用 golang.org/x/text/search 配合 search.IgnoreCase 进行路径分割。存在两个独立缺陷：(1) 控制流缺陷——内层循环遇到非 ASCII 字节时 break 但未将 match 设为 false，导致外层误判匹配成功；(2) Unicode 规范化缺陷——搜索器对 Unicode 等价字符进行规范化处理，使得攻击者可以构造特殊 URL 绕过 .php 扩展名检查。攻击者可将任意非 .php 文件（如上传的图片、文本文件）当作 PHP 脚本执行，实现远程代码执行。

影响产品：FrankenPHP ⭐11,141 — 现代 PHP 应用服务器

影响版本：1.11.2 至 1.12.2（含）

攻击面：任何允许用户上传文件或写入内容的 FrankenPHP 部署。攻击者需能控制服务器上的某个文件内容（如上传图片、日志文件等），然后构造特殊 URL 触发 CGI 路径分割缺陷。

触发条件：请求路径中包含非 ASCII 字节 + 攻击者可在服务器上放置可控内容的文件。利用 Unicode 等价字符或控制流缺陷绕过 .php 扩展名检查。

潜在危害：远程代码执行（RCE）。在允许文件上传的场景下，攻击者可上传包含 PHP 代码的文件（如伪装为图片），然后通过路径分割漏洞使其被 PHP 引擎执行，完全控制服务器。

可利用性：公告包含完整的漏洞源码（splitPos 函数全文）、两个独立缺陷的详细分析、Go 代码级别的触发逻辑说明。由 @KC1zs4 报告，信息极为详尽。

修复建议：立即升级至 FrankenPHP v1.12.3。该版本修复了 splitPos() 函数的控制流和 Unicode 处理缺陷。

🔴 Pipecat: Path Traversal in Runner /files Endpoint — Arbitrary File Read via %2F Encoding
GHSA-3363-2ph6-35wh | CVE: CVE-2026-44716
优先级: 9.3/10
High ⭐ 12,759 🔴 完整PoC + 代码分析 📖 详细分析

漏洞描述：Pipecat 开发运行器（src/pipecat/runner/run.py）在使用 --folder 参数启动时，暴露了 GET /files/{filename:path} 文件下载端点。filename 路径参数直接与 args.folder 拼接，无任何路径包含性检查。Starlette 框架会规范化 URL 中的 ../ 序列，但 %2F 编码的斜杠可绕过此规范化——路径参数在路由匹配后才进行 URL 解码，因此 ..%2F..%2Fetc%2Fpasswd 可解析为基础目录上级路径。攻击者可通过单个未认证 HTTP 请求读取 Pipecat 进程有权限访问的任何文件，包括 SSH 私钥、凭证和系统文件。

影响产品：Pipecat ⭐12,759 — 开源语音和多模态对话 AI 框架

影响版本：0.0.90 至 1.2.0（不含）

攻击面：任何使用 pipecat run --folder 启动并暴露网络访问的开发/生产环境。Pipecat 是热门的 AI 语音对话框架，开发环境常缺乏严格访问控制。

触发条件：攻击者发送包含 %2F 编码路径遍历序列的 HTTP GET 请求即可，无需认证。例如：GET /files/..%2F..%2F..%2Fetc%2Fpasswd

潜在危害：任意文件读取。可泄露服务器上的 SSH 私钥、数据库凭证、API 密钥、环境变量等敏感信息，可能导致进一步的系统入侵。

可利用性：公告包含完整的漏洞代码（run.py 第 249-264 行）、详细的 %2F 绕过原理解释、具体利用 payload 示例。在 pipecat-ai 1.1.0 上已验证。

修复建议：立即升级至 pipecat-ai v1.2.0。若暂时无法升级，避免在公网暴露 Pipecat 开发运行器，或添加网络层访问控制。

GHSA-qvv5-jq5g-4cgg | CVE: CVE-2026-48063
优先级: 9.0/10
Critical ⭐ 9,723 📖 详细分析

漏洞描述：Baileys（最流行的 WhatsApp Web API 库之一）存在严重漏洞：任何使用 < 7.0.0-rc12 或 < 6.7.22 版本的 Baileys 会话都可被发送恶意 placeholderResendMessage 载荷，触发伪造的 messages.upsert 事件，包含伪造的消息 key 和内容。同一漏洞还允许攻击者通过发送伪造 key shares 来破坏 app state sync 系统，并允许历史同步欺骗——注入伪造的历史上下文或"按需"同步消息。这意味着攻击者可以向 WhatsApp 机器人/自动化系统注入任意伪造消息。

影响产品：Baileys (@whiskeysockets/baileys) ⭐9,723 — WhatsApp Web 的 Socket API

影响版本：< 6.7.22 和 >= 7.0.0-rc.1 且 < 7.0.0-rc12

可利用性：公告描述了具体攻击向量（placeholderResendMessage），并提供了临时缓解措施（过滤含 requestId 的 upsert 事件、关闭自动历史同步），间接暴露了攻击细节。修复 commit 已公开。

修复建议：立即升级至 Baileys v7.0.0-rc12 或 v6.7.22。临时缓解：在 socket 配置中设置 shouldSyncHistoryMessage: () => false，并丢弃包含 requestId 字段的 messages.upsert 事件。

🔴 Fission: Router Exposes /fission-function/<ns>/<name> on Public Listener, Bypassing HTTPTrigger
GHSA-3g33-6vg6-27m8 | CVE: CVE-2026-46614
优先级: 8.8/10
Critical ⭐ 8,864 📖 详细分析

漏洞描述：Fission（Kubernetes Serverless 框架）的路由器为每个 Function 对象注册了内部路由 /fission-function/<name> 和 /fission-function/<ns>/<name>，无论是否存在对应的 HTTPTrigger。这些路由与用户定义的 HTTPTrigger 挂载在同一公开监听器上（svc/router，端口 8888），导致任何能访问路由器的调用者都可通过猜测函数的 metadata.name（和命名空间）来调用任意函数，完全绕过 HTTPTrigger 配置的 host/path/method/method-allow-list 限制。

影响产品：Fission ⭐8,864 — Kubernetes 上的 Serverless 函数框架

影响版本：≤ 1.22.0

攻击面：所有 Fission 部署，特别是路由器通过 Ingress 暴露到公网的场景。在多租户部署中，租户 A 的 Pod 可访问租户 B 命名空间中的函数。

触发条件：攻击者只需知道目标函数的名称和命名空间，即可通过 GET/POST /fission-function/<ns>/<name> 直接调用，无需任何认证。

潜在危害：(1) 调用未公开的函数（如 Kubewatcher、Timer、MessageQueue 触发目标、内部辅助函数）；(2) 绕过 HTTPTrigger 的访问控制限制；(3) 通过探测响应状态码枚举函数名称；(4) 多租户环境下跨租户访问。

可利用性：公告包含精确的漏洞代码位置（pkg/router/httpTriggers.go:280-284）、详细的根因分析、完整的影响场景说明和修复方案。漏洞触发极为简单——仅需构造 URL。

修复建议：升级至 Fission v1.23.0。该版本将路由器拆分为两个独立监听器——公开监听器（端口 8888）仅服务 HTTPTrigger，内部监听器服务函数间调用。

GHSA-8qhj-4f8c-j8qg | CVE: CVE-2026-49396
优先级: 8.5/10
High ⭐ 10,112 📖 详细分析

漏洞描述：Nezha（轻量级服务器监控和运维工具）的 Dashboard 将 cron 手动触发操作暴露为认证 GET 端点 /api/v1/cron/:id/manual。Dashboard 的 JWT 通过 nz-jwt cookie 传递，配置为 SameSite=Lax，浏览器会在顶级跨站 GET 导航中包含此 cookie。由于该状态变更 GET 端点没有 CSRF token、来源验证或 fetch-metadata 保护，攻击者可通过在恶意页面中嵌入链接，使已登录的 Nezha 用户触发其已配置的 cron 任务。

影响产品：Nezha ⭐10,112 — 自托管轻量级服务器监控和运维工具

影响版本：≥ 1.0.0 且 < 2.0.14

攻击面：所有 Nezha Dashboard 实例。攻击者只需诱导已登录管理员访问恶意页面即可。Nezha 广泛用于服务器监控场景，管理员通常保持登录状态。

触发条件：攻击者构造包含 <a href="https://victim-nezha/api/v1/cron/:id/manual"> 的恶意页面，诱导已登录管理员点击或访问。SameSite=Lax cookie 会在顶级导航中自动携带。

潜在危害：攻击者可触发管理员已配置的 cron 任务，这些任务可能在受监控的 agent 服务器上执行任意命令。如果管理员配置了高权限的运维脚本（如系统更新、服务重启等），攻击者可间接在目标服务器上执行这些操作。

可利用性：公告详细描述了 CSRF 利用链：SameSite=Lax cookie 行为、具体 API 端点路径、攻击 payload 构造方式。利用门槛极低——仅需一个恶意网页链接。

修复建议：升级至 Nezha v2.0.14。将 cron 手动触发改为 POST 方法，添加 CSRF token 或 SameSite=Strict cookie 配置。
