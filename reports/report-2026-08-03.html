🟠 Docling: Unsafe URI and Path Handling in HTML Backend
GHSA-q29v-xc37-wh5m | CVE: CVE-2026-47214
优先级: 高
High ⭐ 64,129 📖 详细分析

漏洞描述：Docling 是一个用于将各种文档格式（PDF、DOCX、PPTX、XLSX、HTML等）转换为AI就绪格式的流行开源库。其 HTML 后端在处理资源时未进行充分验证，存在多个安全问题，可能导致本地文件系统访问、路径遍历攻击、SSRF（服务器端请求伪造）以及资源耗尽攻击。

影响产品：docling ⭐ 64,129

影响版本：< 2.94.0（2.91.0 版本进行了初步修复，2.94.0 版本进行了额外改进）

攻击面：

  • 本地文件系统访问：接受 file:// URI，当 enable_local_fetch=True 时可访问本地文件系统
  • 路径遍历：通过 ../ 序列和绝对路径可遍历到预期目录之外
  • SSRF：在 enable_remote_fetch=True 时未阻止内部网络资源访问
  • HTTP 重定向攻击：未验证 HTTP 重定向，可能重定向到非预期协议
  • 资源耗尽：对远程图片下载和 data: URI 无资源大小限制

触发条件：应用程序使用 Docling 处理不受信任的 HTML 文档，且启用了 enable_local_fetch 或 enable_remote_fetch 选项。

潜在危害：

  • 敏感文件泄露（如 /etc/passwd、配置文件、密钥文件）
  • 内部网络探测和数据窃取
  • 拒绝服务攻击（通过大文件下载或无限重定向）
  • 可能的远程代码执行（结合其他漏洞）

可利用性：有详细漏洞原理说明，包含具体的攻击向量和触发机制。攻击者只需构造恶意 HTML 文档即可触发漏洞。

修复建议：

  • 立即升级到 docling >= 2.94.0
  • 如无法立即升级，保持 enable_local_fetch=False 和 enable_remote_fetch=False（默认值）
  • 审查所有使用 Docling 处理外部 HTML 的代码路径
  • 实施输入验证，确保只处理受信任来源的文档

CVSS 评分：7.1 (High) - CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:L

CWE 类型：

  • CWE-73: 外部控制文件名或路径
  • CWE-400: 不受控制的资源消耗
