🔴 Traefik StripPrefix 路由级认证绕过 (Path Normalization)
GHSA-xf64-8mw2-4gr2 | CVE: CVE-2026-48020
优先级: 极高
High ⭐ 63,636 🔴 完整PoC 📖 详细分析

漏洞描述：Traefik 的 StripPrefix 中间件存在路由级认证/授权绕过漏洞。当公共路由器匹配 PathPrefix 规则并应用 StripPrefix 中间件时，攻击者可以通过在请求路径中使用 .. 或其百分号编码形式 %2e%2e，在路由阶段匹配公共路由，但在前缀剥离和路径规范化后，解析为受认证路由器提供的路径。这使攻击者无需满足认证中间件要求即可访问受保护的后端路径（如管理面板或内部配置端点）。

影响产品：Traefik ⭐63,636

影响版本：v2 < 2.11.48, v3 < 3.6.19, v3.7.x < 3.7.3

攻击面：任何使用 StripPrefix + PathPrefix 路由规则并配合认证中间件的 Traefik 部署，未认证远程攻击

触发条件：发送包含 /api../admin 或 /api%2e%2e/admin 的请求即可绕过路由认证

潜在危害：未授权访问管理接口、内部配置端点，可能导致整个后端服务被接管

可利用性：有完整PoC和复现步骤，包含Docker Compose环境配置和curl命令

修复建议：立即升级到 v2.11.48 / v3.6.19 / v3.7.3 及以上版本。如无法立即升级，审查所有使用 StripPrefix 的路由配置，避免公共路由与受保护路由共用 PathPrefix 前缀。

🔴 Axios 原型链污染导致完全中间人攻击 (config.proxy)
GHSA-35jp-ww65-95wh | CVE: CVE-2026-44494
优先级: 极高
High (CVSS 9.4) ⭐ 109,074 🔴 完整PoC 📖 详细分析

漏洞描述：Axios 存在原型链污染 Gadget 漏洞，允许将应用依赖树中任何 Object.prototype 污染升级为完全中间人(MITM)攻击——拦截、读取和修改所有HTTP流量，包括认证凭据。HTTP适配器在 lib/adapters/http.js:670 通过标准属性访问读取 config.proxy，由于 proxy 不存在于 Axios 默认配置中，攻击者仅需设置 Object.prototype.proxy = {host:'attacker', port:8080} 即可将所有请求路由到攻击者代理。

影响产品：axios ⭐109,074

影响版本：1.0.0 - 1.15.x（所有 v1.x 版本，含 v1.15.0）

攻击面：Node.js 环境使用 axios 发送 HTTP 请求的应用，需存在另一个原型链污染漏洞作为前置条件

触发条件：同进程存在原型链污染漏洞 + 使用 axios 发起 HTTP 请求

潜在危害：窃取所有 HTTP 请求中的认证凭据（Token/Cookie）、篡改响应数据、完全控制 API 通信

可利用性：有完整PoC，包含概念验证代码和利用链分析。无需用户交互，零约束条件

修复建议：升级到 axios v1.16.0+。同时审计依赖树中其他原型链污染漏洞，使用 Object.create(null) 替代 {} 初始化配置对象。

🟠 Netty DNS Codec 输入验证绕过（编码器+解码器）
GHSA-cm33-6792-r9fm | CVE: CVE-2026-42579
优先级: 高
High ⭐ 34,972 🔴 完整PoC 📖 详细分析

漏洞描述：Netty 的 DNS 编解码器在编码和解码时均未强制执行 RFC 1035 域名约束。编码器侧存在空字节注入（CWE-626），允许域名中包含空字节导致不同 DNS 实现产生不同解析结果（DNS 缓存投毒）。解码器侧缺少每标签长度验证（最大63字节）和总域名长度验证（最大255字节），攻击者可通过恶意 DNS 响应触发无界 StringBuilder 增长。

影响产品：Netty (netty-codec-dns) ⭐34,972

影响版本：4.2.0.Alpha1 - 4.2.12.Final, <= 4.1.132.Final

攻击面：使用 Netty DNS 编解码器的应用，双向攻击面（恶意 DNS 响应 + 用户可控主机名）

触发条件：编码：用户可控域名含空字节/超长标签；解码：恶意 DNS 响应

潜在危害：DNS 缓存投毒、域名验证绕过、拒绝服务（内存耗尽）、畸形 DNS 数据包

可利用性：有完整PoC，包含详细的代码行级分析和 RFC 1035 对比

修复建议：升级到 4.2.13.Final+ / 4.1.133.Final+。

可利用性：有完整PoC，Node.js 22.11.0 即可复现，无需第三方依赖

修复建议：升级到 v3.0.7+。避免直接将不可信 JSON 数据作为 cookie 属性参数。
