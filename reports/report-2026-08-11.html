🔴 Flyto2 Core: Unauthenticated flyto-verification /run: callback_url SSRF and internal runner-secret exfiltration
GHSA-jx74-cqjv-2c67 | CVE: CVE-2026-67426
优先级: 68/100
CRITICAL⭐ 479🔴 PoC Available📖 详细分析

漏洞描述：Flyto2 Core 的 flyto-verification 服务在 POST /run 端点无任何身份认证，且绑定在所有网络接口(0.0.0.0:8344)。请求体中的 callback_url 被直接用于出站 POST 请求，并自动附加 X-Internal-Key: $FLYTO_RUNNER_SECRET 头部。该 callback_url 绕过了 target_allowed 白名单检查（仅检查 params.target_url），且未经过任何 SSRF 防护。

影响产品：pip/flyto-core ⭐479

影响版本：flyto-core: >= 2.26.6, < 2.26.7 (修复: 2.26.7)

攻击面：未认证攻击者可通过构造恶意 callback_url 实现：(1) 对内网/云元数据端点的 SSRF 攻击；(2) 窃取 FLYTO_RUNNER_SECRET 到攻击者控制的服务器，进而伪造认证回调。

触发条件：发送 POST 请求到 /run 端点，在请求体中指定恶意 callback_url

潜在危害：SSRF + 内部密钥泄露，可能导致内网渗透和认证绕过

可利用性：有完整PoC - 包含技术细节: 'POST '; - 包含具体攻击路径和参数; - 包含修复commit: 1个

修复建议：升级到 flyto-core >= 2.26.7；对 /run 端点添加身份认证；对 callback_url 进行白名单校验

🟠 fast-uri vulnerable to path traversal via percent-encoded dot segments
GHSA-q3j6-qgpj-74h6 | CVE: CVE-2026-6321
优先级: 43/100
HIGH⭐ 119📖 详细分析

漏洞描述：fast-uri v3.1.0 及更早版本在 normalize() 和 equal() 函数中，会在执行 dot-segment 移除之前先解码 percent-encoded 的路径分隔符(%2F)和点段(%2E)。这导致编码后的路径数据表现得像真实的 / 和 ..，不同的 URI 会折叠到相同的规范化路径。

影响产品：npm/fast-uri, npm/fast-uri ⭐119

影响版本：fast-uri: >= 3.0.0, <= 3.1.0 (修复: 3.1.1); fast-uri: <= 2.4.0 (修复: 2.4.1)

攻击面：攻击者可利用此漏洞绕过基于路径的访问控制策略。例如 http://example.com/public/%2e%2e/admin 会被规范化为 http://example.com/admin，使看似受限的路径可以访问任意位置。

触发条件：构造包含 percent-encoded dot segments 的 URL，利用 normalize/equal 函数的不一致行为

潜在危害：路径遍历绕过，可能导致未授权访问受限资源

可利用性：有详细原理 - 包含技术细节: 'attacker-controlled'; - 包含编码绕过示例

修复建议：升级到 fast-uri >= 3.1.1 或 v2.4.1

🟠 fast-uri vulnerable to host confusion via percent-encoded authority delimiters
GHSA-v39h-62p7-jpjc | CVE: CVE-2026-6322
优先级: 43/100
HIGH⭐ 119📖 详细分析

漏洞描述：fast-uri v3.1.1 及更早版本在 host 组件中会解码 percent-encoded 的 authority 分隔符（%40 解码为 @，%3A 解码为 :）并将其序列化为原始字符，这会改变 URI 结构，将主机名变为 userinfo 加不同的 host。

影响产品：npm/fast-uri, npm/fast-uri ⭐119

影响版本：fast-uri: >= 3.0.0, <= 3.1.1 (修复: 3.1.2); fast-uri: <= 2.4.0 (修复: 2.4.1)

攻击面：例如 http://trusted.com%40evil.com/ 被规范化为 http://trusted.com@evil.com/，重新解析后 host 变为 evil.com，userinfo 为 trusted.com。攻击者可利用此特性在 host 白名单检查、重定向验证或出站请求路由时，将请求导向恶意主机。

触发条件：构造包含 percent-encoded authority delimiters 的 URL，利用规范化后的 host confusion

潜在危害：Host 混淆，可能导致开放重定向、SSRF 或认证绕过

可利用性：有详细原理 - 包含编码绕过示例

修复建议：升级到 fast-uri >= 3.1.2 或 v2.4.1
