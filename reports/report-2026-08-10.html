🔴 Microsoft Kiota: 通过 x-ms-kiota-info 实现命令注入导致 RCE
GHSA-hq9q-27g5-qwpj | CVE: CVE-2026-59865
优先级: 极高
Critical ⭐ 3,798 (Microsoft) 🔴 PoC Available 📖 详细分析

漏洞描述：Microsoft Kiota 的 kiota info 命令直接读取 OpenAPI 描述文件中的 x-ms-kiota-info 扩展，将攻击者控制的 dependencyInstallCommand 作为工具推荐安装命令展示给开发者。开发者执行该命令即导致远程代码执行（RCE）。VS Code 扩展也会消费该恶意输出，可能自动执行攻击者命令。

影响产品：Microsoft Kiota (nuget/Microsoft.OpenApi.Kiota) ⭐ 3,798

影响版本：< 1.32.5

攻击面：开发者运行 kiota info 处理不受信任的 OpenAPI 描述文件时触发。VS Code Kiota 扩展自动消费 JSON 输出，可能自动执行恶意命令。

触发条件：开发者使用 kiota info 命令处理恶意 OpenAPI spec，或 VS Code 扩展自动触发依赖安装流程。

潜在危害：完整远程代码执行，开发者工作站和 CI 环境沦陷。供应链攻击向量。

可利用性：有完整 PoC 代码（公告中包含恶意 spec 示例）+ 修复 PR + 提交记录。攻击只需构造恶意 OpenAPI 描述文件。

修复建议：立即升级至 Kiota ≥ 1.32.5，更新 VS Code Kiota 扩展。该版本完全移除了对 spec 提供的 dependencyInstallCommand 的支持。

🔴 crypto-js: 依赖链漏洞导致加密密钥生成熵不足，加密货币钱包遭窃
GHSA-rg76-677x-56q9 | CVE: CVE-2026-71851
优先级: 极高
Critical (CVSS 9.0) ⭐ 16,398 🔴 PoC Available 📖 详细分析

漏洞描述：crypto-js < 4.0.0 的 lib/random.js 回退使用 MWC 伪随机数生成器（种子仅为毫秒级时间戳），熵空间不足 2^40。通过约 4000 次观察输出即可恢复种子和内部状态。已确认有攻击者利用此漏洞从约 19,000 个地址窃取了 220 万美元以上的加密货币资产。

影响产品：crypto-js (npm/crypto-js) ⭐ 16,398

影响版本：< 4.0.0（仅当 crypto-js 是最近的依赖时才受影响，4.0.0+ 已不再依赖 vulnerable bip39 分支）

攻击面：通过 bip39 库间接影响所有使用 crypto-js 生成助记词的加密钱包应用。也影响 ferrumnet 等直接依赖受影响 bip39 分支的项目。

触发条件：应用使用 crypto-js < 4.0.0 作为传递依赖，且通过 bip39 生成加密密钥/助记词。

潜在危害：加密资产被盗。已确认超过 220 万美元损失。攻击者可被动恢复私钥种子。

可利用性：有完整 PoC + Coinspect 调查报告 + Ill Bloom 在线检查工具 + 技术细节分析。CVSS 3.1 评分 9.0。

修复建议：1) 检查依赖树中是否存在 crypto-js < 4.0.0；2) 审查受影响钱包并轮换密钥；3) 避免在生产加密应用中依赖 crypto-js。

🔴 Keras: Lambda 反序列化绕过 Safe Mode 执行任意代码
GHSA-5gwj-m78q-7pq3 | CVE: CVE-2026-12481
优先级: 极高
High (CVSS 8.8) ⭐ 64,221 📖 详细分析

漏洞描述：Keras 的 Lambda 层反序列化函数 _raise_for_lambda_deserialization() 在 safe_mode 为 None（默认值）时未能正确执行安全检查，将"未设置"与"显式禁用"混淆，导致攻击者控制的 marshal 字节码可被反序列化执行，实现任意 OS 级代码执行。

影响产品：Keras (pip/keras) ⭐ 64,221

影响版本：< 3.12.3 及 3.13.0~3.15.0

攻击面：任何处理不受信任 Keras 模型配置的服务端/用户进程。攻击入口包括 keras.layers.deserialize()、keras.models.clone_model() 等。

触发条件：加载恶意构造的 Keras 模型配置文件（含 Lambda 层 marshal 字节码），且未显式设置 SafeModeScope。

潜在危害：完整远程代码执行，服务器沦陷。ML 模型服务、模型仓库成为攻击目标。

可利用性：有详细漏洞原理 + 触发代码路径分析。huntr.com 赏金报告。

修复建议：升级至 keras ≥ 3.15.0。确保在 SafeModeScope(True) 上下文中加载外部模型。
