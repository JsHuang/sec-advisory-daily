🔴 紧急 SeaweedFS: Unauthenticated SSRF with response read-back via VolumeServer.FetchAndWriteNeedle
GHSA-87fv-vqqr-m4jr | CVE: CVE-2026-73080 | CWE: CWE-918
优先级: 10/12
CRITICAL⭐ 34,023CVSS: 9.3🔴 PoC Available📖 详细分析

漏洞描述：SeaweedFS的VolumeServer.FetchAndWriteNeedle RPC在4.24版本之前未进行任何身份验证，也未验证目标地址。任何能够访问volume server gRPC端口的攻击者都可以强制服务器向任意主机发起请求——包括回环地址、链路本地地址、RFC 1918私有地址和云元数据端点(如169.254.169.254)——并读回响应。在云环境中，这会泄露实例元数据和IAM凭证。

影响产品：SeaweedFS ⭐ 34,023

影响版本：< 0.0.0-20260512171120-69da20bdaec9

攻击面：gRPC端口（默认无认证），任何可达volume server的网络位置

触发条件：向volume server的gRPC端口发送FetchAndWriteNeedle请求，指定内网/元数据目标URL

潜在危害：SSRF带响应读取，可窃取云环境IAM凭证、访问内网服务、绕过防火墙策略

可利用性：有详细原理

修复建议：升级到4.24版本，该版本添加了admin授权要求和目标地址过滤（回环/链路本地/RFC1918/IMDS）；或通过防火墙限制gRPC端口访问

优先级: 8/12
HIGHN/ACVSS: 7.5🔴 PoC Available📖 详细分析

漏洞描述：pytonapi 2.2.0的TonapiWebhookDispatcher在webhook handler使用path=参数注册时，未能验证Authorization头。setup()期间bearer token仅存储在默认后缀路径下（如/hook/account-tx），但自定义路径（如/hook/custom）从未添加到token映射中。当请求到达自定义路径时，self._tokens.get(path)返回None，导致认证检查被静默跳过。未认证的远程攻击者可向自定义webhook端点POST任意伪造payload。

影响产品：pytonapi（TON区块链API库） N/A

影响版本：>= 2.0.0, < 2.2.1

攻击面：使用pytonapi webhook dispatcher并注册自定义路径的TON应用

触发条件：向自定义webhook路径发送未携带Authorization头的POST请求

潜在危害：完全绕过webhook认证，攻击者可注入伪造的交易通知触发应用逻辑

可利用性：有完整PoC

修复建议：升级到pytonapi >= 2.2.1

可利用性：有详细原理

修复建议：升级到golang.org/x/crypto >= 0.52.0，该版本正确序列化所有约束扩展

🟠 高危 golang.org/x/crypto: Invoking client can cause server deadlock on unexpected responses
GHSA-vgwf-h737-ff37 | CVE: CVE-2026-39830 | CWE: CWE-119, CWE-772
优先级: 8/12
CRITICAL⭐ 3,336CVSS: 9.1📖 详细分析

影响产品：golang.org/x/crypto (SSH库) ⭐ 3,336

影响版本：< 0.52.0

攻击面：任何使用golang.org/x/crypto/ssh的服务端或客户端

触发条件：恶意SSH对端发送意外的全局请求响应（unsolicited global request responses）

潜在危害：资源泄漏导致服务不可用（DoS），每个恶意连接泄漏一个goroutine

可利用性：有详细原理

修复建议：升级到golang.org/x/crypto >= 0.52.0，该版本会丢弃未经请求的全局响应
